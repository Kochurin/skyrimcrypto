# SkyrimCrypto

SkyrimCrypto — текстовый редактор с клиентским шифрованием (Zero-Knowledge Cloud Notepad).
Заметка шифруется в браузере; сервер хранит только зашифрованный пакет и не знает ни пароля, ни текста.

Проект реализует модель из лабораторных работ 1–7 («Современные подходы и методы автоматизации деятельности организации»).
Техническое решение — Sol_5 из ЛР3: Web Crypto API, монолит на Node.js, PostgreSQL, S3-хранилище.

## Структура (компоненты из ЛР7)

| Папка | Компонент | Статус |

## Запуск

```
npm install
docker compose up -d      # PostgreSQL :5432 и MinIO :9000 (консоль :9001), только localhost
npm run dev:api           # сервер на http://127.0.0.1:8787, миграции применяются сами
npm run dev:web           # редактор на http://127.0.0.1:5173 (запросы /api проксируются на :8787)
```

В PowerShell с запретом сценариев вместо `npm` пишите `npm.cmd`.

Настройки — переменные окружения (по умолчанию совпадают с `.env.example`; файл `.env` в корне подхватывается автоматически).

## API (IF2 INotesApi)

| Метод | Путь | Ответ |
|---|---|---|
| `POST` | `/api/notes?ttl=1\|7\|30` | тело — зашифрованный пакет v1 → `201 {id, expiresAt, owned}`; `400 INVALID_PACKAGE / BAD_TTL`; `413 TOO_LARGE`. После входа заметка привязывается к владельцу |
| `GET` | `/api/notes/:id` | `200` пакет v1 или `404 NOT_FOUND` (без уточнения причины) |
| `GET` | `/api/notes` | список своих заметок `{notes: [{id, sizeBytes, createdAt, expiresAt}]}`; без входа `401` |
| `DELETE` | `/api/notes/:id` | `204`; чужая — `403 FORBIDDEN`; без входа `401`; нет — `404` |
| `POST` | `/api/auth/register` | `{login, password}` → `201 {login, role}` + cookie; `409 LOGIN_TAKEN`; `400 BAD_LOGIN / WEAK_PASSWORD` |
| `POST` | `/api/auth/login` | `200 {login, role}` + cookie; `401 INVALID_CREDENTIALS`; `429 LOCKED` |
| `POST` | `/api/auth/logout` | `204`, cookie стирается |
| `GET` | `/api/auth/me` | `200 {login, role}` или `401` |
| `GET` | `/api/health` | `200 {status:"ok", db, s3}` или `503 degraded` |

Все ответы с заголовком `Cache-Control: no-store`. Сервер не расшифровывает пакеты: он проверяет только структуру.

Хранение (ЛР7): шифротекст — объект `notes/<id>` в MinIO (D1), заголовок пакета (соль, IV, итерации) — строка таблицы `notes` в PostgreSQL (D2).
Сохранение атомарное (NFR-05): сначала блоб, затем строка в БД; если запись в БД не удалась, блоб удаляется.
Срок хранения — 30 дней (`NOTE_TTL_DAYS`). Название заметки на сервер не передаётся: оно должно быть частью зашифрованного текста.

## Учётные записи (FR-01, FR-05, FR-06, FR-09)

- **Пароль учётной записи — не пароль заметок.** Он открывает список своих заметок и позволяет удалять их, но не расшифровывает: каждая заметка по-прежнему зашифрована своим паролем в браузере.
- Хеш пароля — Argon2id (`@node-rs/argon2`, m = 19 МиБ, t = 2, p = 1). Неверный логин и неверный пароль дают одинаковый ответ; для несуществующего логина тоже вычисляется хеш, чтобы время ответа не выдавало, есть ли такой пользователь.
- 5 неудачных попыток подряд — вход блокируется на 15 минут (`429 LOCKED`), даже с верным паролем.
- Сессия — JWT (HS256, 12 ч, в токене id и роль) в cookie `sc_session`: `HttpOnly` (скрипты страницы его не видят), `SameSite=Strict` (защита от CSRF), `Path=/api`, `Secure` — при `COOKIE_SECURE=true`. Роль при каждом запросе берётся из БД.
- Роли `author` / `auditor` / `admin` заложены в таблицу `users`; разделы для аудитора и администратора — этап 6.
- Список «Мои заметки» содержит только метаданные: дату, размер, срок. Названий в нём нет — они зашифрованы вместе с текстом (в ЛР6 у FR-06 есть «название» и поиск по нему; здесь от этого сознательно отказались ради Zero-Knowledge).
- Удаление (FR-09): строка помечается `deleted_at` (ссылка сразу даёт 404), затем удаляется блоб в MinIO, затем строка. Если MinIO недоступен, строка остаётся помеченной, и удаление повторит очистка.
- Очистка (FR-09): при запуске сервера и раз в `PURGE_INTERVAL_MINUTES` (по умолчанию 60) удаляются просроченные и помеченные заметки — сначала блоб, потом строка.
- Срок хранения выбирается при создании: 1, 7 или 30 дней. Без входа заметку нельзя удалить вручную — только по сроку.
- Выход стирает cookie; сам JWT до истечения срока не отзывается (список отозванных токенов — этап 5).

## Веб-редактор (K1.1)

- `/` — US-01: название и текст → пароль дважды → шифрование в браузере → ссылка `/n/<id>`. Ссылку и пароль передают разными каналами.
- `/login` — вход и регистрация; `/notes` — «Мои заметки» с удалением (подтверждение перед удалением).
- `/n/<id>` — US-02: загрузка пакета → пароль → расшифровка в браузере. Неверный пароль и подмена данных дают одно сообщение (тег GCM не сошёлся).
- Название шифруется вместе с текстом: внутри шифротекста лежит `{"type":"cn-note","v":1,"title","text"}`.
- Ошибки сценариев: нет Web Crypto (кнопка неактивна, ничего не отправляется), короткий пароль, пароли не совпадают, больше 10 МБ, сервер недоступен (текст остаётся в редакторе), 404.
- Пароль и текст живут только в состоянии страницы: не пишутся в localStorage, после сохранения пароль стирается. Текст выводится только текстовыми узлами React — `innerHTML` не используется.

## Формат зашифрованного пакета (v1)

```json
{
  "v": 1,
  "kdf":    { "alg": "PBKDF2-SHA256", "iterations": 600000, "salt": "<16 байт, base64url>" },
  "cipher": { "alg": "AES-256-GCM", "iv": "<12 байт, base64url>" },
  "ciphertext": "<шифротекст + тег 16 байт, base64url>"
}
```

- Ключ: PBKDF2-HMAC-SHA-256, 600 000 итераций по умолчанию (допускается 100 000 – 10 000 000), соль 16 байт из CSPRNG, пароль в NFC.
- Шифр: AES-256-GCM, новый IV 12 байт на каждое шифрование, тег 128 бит.
- Заголовок (версия, алгоритмы, итерации, соль, IV) передаётся в GCM как AAD: его подмена обнаруживается так же, как подмена шифротекста.
- Ключ неэкспортируемый (`extractable: false`).
